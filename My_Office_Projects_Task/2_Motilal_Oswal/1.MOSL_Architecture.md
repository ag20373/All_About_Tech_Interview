# Motilal Architecture

## 1. Overview

Motilal Architecture ko broadly **3 main components** mein divide kiya
ja sakta hai:

1.  **Client Dispatcher**
2.  **Client-Side Application**
3.  **Server-Side Application**

Ye teeno components milkar client aur server ke beech communication
establish karte hain. Client-side applications se aane wali requests
Client Dispatcher ke through server-side applications tak pahunchti
hain. Server se generate hone wala response wapas Client Dispatcher ke
through relevant client application ko send kiya jata hai.

## 3. Client-Side Application

Client-Side Applications woh applications hoti hain jinhe clients
directly use karte hain. Examples:

-   Mobile Applications
-   iOS Applications
-   Windows Applications
-   Other supported client applications

### Main Responsibilities

-   Client-side application ka primary purpose client ki request
    generate karna aur use **Client Dispatcher** ke through server tak
    forward karna hai.
-   Client apne **Orders, Trades, Portfolio aur Margin Reports** jaise
    details in applications par dekh sakta hai.
-   Application server se aane wale responses ko receive karke relevant
    information client ko display karti hai.
-   Client applications server ke saath network communication establish
    karti hain. Architecture aur use case ke according communication
    mein **TCP/IP** aur **Multicast** jaise mechanisms use ho sakte
    hain.

## 4. Client Dispatcher

Client Dispatcher architecture ka **middleware component** hai. Ye
Client-Side Applications aur Server-Side Applications ke beech
communication bridge ka kaam karta hai.

### Main Responsibilities

-   Client-side application se aane wali requests ko receive karna.
-   Requests ko appropriate server-side application ya handler tak route
    karna.
-   Server-side applications se aane wale responses ko receive karna.
-   Responses ko correct client-side application tak wapas forward
    karna.
-   System configuration ke according Multicast IP aur port ka use karke
    communication channels establish ya manage karna.

**Simple words mein:** Client Dispatcher ka main kaam client aur server
ke beech data/request-response communication ko manage karna hai.

## 5. Server-Side Applications

System mein multiple Server-Side Applications hoti hain. Har application
ki responsibility alag hoti hai. Ye applications client requests ko
process karti hain aur required response generate karti hain.

### 5.1 Login Handler

-   Client ke login request ko process karta hai.
-   Login credentials aur applicable authentication checks ke basis par
    login response generate karta hai.
-   Login successful ya unsuccessful hone ka response client tak bhejta
    hai.

### 5.2 Report Handler

Report Handler client ke account aur trading activity se related reports
generate karta hai.

Examples:

-   Client Positions
-   Order Book
-   Trade Book
-   Margin Report

Ye reports client ki request ke according generate hoti hain aur
response Client Dispatcher ke through client application tak pahunchta
hai.

### 5.3 Risk Engine

Risk Engine trading system ka important component hai. Ye client ke
orders aur risk-related checks ko manage karta hai.

-   Client orders ko process karta hai.
-   Applicable risk checks aur validations perform karta hai.
-   Order management workflow mein important role play karta hai.
-   Risk rules ke basis par order ko allow, reject ya further processing
    ke liye route kar sakta hai.

### 5.4 Exchange Dispatcher

Exchange Dispatcher ka primary purpose client ke eligible orders ko
exchange tak route karna hai.

-   Risk Engine ya relevant order-processing workflow se aane wale
    orders receive karta hai.
-   Orders ko exchange connectivity layer ke through exchange tak
    forward karta hai.
-   Exchange se aane wale acknowledgements, order updates ya responses
    ko system ke relevant components tak route karta hai.

## 6. End-to-End Request and Response Flow

1.  Client apni application (Mobile, iOS, Windows, etc.) par koi action
    perform karta hai, jaise login karna, report dekhna ya order place
    karna.
2.  Client application request generate karti hai.
3.  Request Client Dispatcher ko send hoti hai.
4.  Client Dispatcher request ko appropriate Server-Side Application tak
    route karta hai.
5.  Relevant server application request process karke response generate
    karti hai.
6.  Response Client Dispatcher ke paas wapas aata hai.
7.  Client Dispatcher response ko correct client application tak forward
    karta hai.
8.  Client application response ko process karke client ko screen par
    display karti hai.

## 7. Quick Summary

  -----------------------------------------------------------------------
  Component                           Main Responsibility
  ----------------------------------- -----------------------------------
  Client-Side Application             Client requests generate karna aur
                                      Orders, Trades, Portfolio, Reports
                                      display karna

  Client Dispatcher                   Client aur server ke beech requests
                                      aur responses ko route karna

  Login Handler                       Login request process karna aur
                                      login response generate karna

  Report Handler                      Positions, Order Book, Trade Book
                                      aur Margin Report generate karna

  Risk Engine                         Order processing aur risk checks
                                      manage karna

  Exchange Dispatcher                 Orders ko exchange tak route karna
                                      aur exchange updates
                                      receive/forward karna
  -----------------------------------------------------------------------

## 8. Overall Architecture in One Line

**Client Application → Client Dispatcher → Relevant Server-Side
Application → Client Dispatcher → Client Application**

Is architecture mein Client Dispatcher communication bridge ka kaam
karta hai, Client-Side Application user interface provide karti hai, aur
Server-Side Applications business logic aur request processing handle
karti hain.
