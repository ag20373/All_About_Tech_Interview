# How Terminals Connect to the Client Dispatcher (CD)

## 1. Basic connection architecture

The Client Dispatcher (CD) acts as a **TCP server**, while each trading terminal acts as a **TCP client**.

Examples of terminals:

- Desktop TWS
- Mobile application
- Third-party API client

Each terminal connects to the CD using its IP address and listening port. Terminals do not connect directly to the Login Server, Risk Server, Report Server, or Exchange.

```text
+----------------------+   +----------------------+   +----------------------+
| Desktop TWS          |   | Mobile App           |   | Third-party API       |
| TCP Client           |   | TCP Client           |   | TCP Client            |
+----------+-----------+   +----------+-----------+   +----------+-----------+
           |                          |                          |
           +--------------------------+--------------------------+
                                      |
                              TCP connections
                                      |
                           IP address + Port
                                      |
                         +------------v-------------+
                         |     CLIENT DISPATCHER    |
                         |       TCP Server         |
                         |                          |
                         |  - Accepts connections   |
                         |  - Maintains sockets     |
                         |  - Identifies terminals  |
                         |  - Routes messages       |
                         +------------+-------------+
                                      |
                     +----------------+----------------+
                     |                |                |
               +-----v-----+    +-----v-----+    +-----v------+
               | Login     |    | Risk      |    | Report     |
               | Server    |    | Validator |    | Server     |
               +-----------+    +-----------+    +------------+
                                      |
                              +-------v--------+
                              | Exchange       |
                              | Adapters       |
                              +----------------+
```

## 2. Step-by-step: How the connection happens

### Step 1: CD starts its TCP listener

When the Client Dispatcher starts:

1. It reads `Dispatcher.xml`.
2. It obtains its `ComponentId`, listener IP address and port, and multicast settings.
3. It starts the network shell and TCP terminal listener.
4. It becomes ready to accept terminal connections.

Example configuration values (illustrative only):

```xml
<Dispatcher>
    <ListenerIP>192.168.1.100</ListenerIP>
    <ListenerPort>5000</ListenerPort>
</Dispatcher>
```

> The actual XML structure and element names in the project may be different. Check the real `Dispatcher.xml` before quoting this example.

### Step 2: Terminal connects to CD

The terminal knows the CD's IP address and port. It opens a TCP connection to that endpoint.

Illustrative C# client example:

```csharp
TcpClient client = new TcpClient();
client.Connect("192.168.1.100", 5000);
```

This is a generic example of a .NET TCP client connection, not confirmed project source code.

### Step 3: CD accepts the connection

On the CD side, the TCP listener accepts the incoming connection. The accepted socket is then available for communication with that terminal.

Illustrative C# server example:

```csharp
TcpListener listener =
    new TcpListener(IPAddress.Any, 5000);

listener.Start();

while (true)
{
    TcpClient terminal = listener.AcceptTcpClient();

    // Handle the connected terminal.
}
```

This demonstrates the general TCP server pattern. It is not a transcription of the project's actual implementation.

### Step 4: CD identifies the terminal

According to the project notes, every packet has a fixed header containing:

- Message code
- Message length
- Error code
- Client or terminal ID
- Client Dispatcher ID

The CD maintains a dictionary called `TerminalCollection`, keyed by terminal ID.

For each terminal, it stores:

- The live socket
- A logged-in flag
- Messages received counter
- Messages sent counter
- Failed messages counter

This allows the CD to associate incoming messages and outgoing replies with the correct terminal connection.

### Step 5: Terminal sends messages

After the TCP connection is established, the terminal sends application messages through that connection.

Examples include:

- Login request
- Place order
- Modify order
- Cancel order
- Download reports

The CD receives the packet, validates it, determines where it should go, forwards it to the relevant component, and routes the reply back to the correct terminal.

## 3. TCP connection vs. application login

These are two different things.

| TCP connection | Application login |
|---|---|
| Establishes communication with the CD | Authenticates the user through the Login Server |
| Creates a socket connection | Establishes the authenticated session |
| Allows the terminal to exchange data with the CD | Allows the user to perform authenticated operations |
| Does not mean the user is logged in | Requires a successful login response |

The project notes describe two connection slots for each terminal:

- `RequestedConnectionContext`: the connection that is currently requesting login.
- `ConnectionContext`: the officially logged-in connection.

When the Login Server returns success, the CD moves the requested connection into the logged-in slot and sends the reply.

If login fails, the CD sends the error and clears the requested slot. This also helps prevent one connection from using another connection's session.

## 4. Interview-ready answer

**Question: How are terminals connected to the Client Dispatcher?**

"Our Client Dispatcher acts as a TCP server, and trading terminals act as TCP clients. When the CD starts, it reads its listener IP address and port from `Dispatcher.xml` and starts the TCP terminal listener.

The terminal connects to that IP address and port using TCP. The CD accepts the connection and maintains the live socket in its `TerminalCollection`, using the Terminal ID as the key.

Every incoming packet contains a fixed header with fields such as Message Code, Message Length, Terminal ID, and Client Dispatcher ID. The CD uses these details to identify the terminal and process its messages.

One important point is that establishing a TCP connection does not mean the user is logged in. Login is a separate process handled by the Login Server."

## 5. Quick revision

- **Terminal:** TCP client.
- **Client Dispatcher:** TCP server.
- **IP address + port:** Endpoint the terminal connects to.
- **TCP listener:** Accepts incoming terminal connections.
- **Socket:** Communication channel between a terminal and the CD.
- **`TerminalCollection`:** CD dictionary that tracks terminal connections and related state.
- **`Terminal ID`:** Identifies the terminal in packet headers and in `TerminalCollection`.
- **TCP connection:** Establishes network communication; it does not authenticate the user.
- **Application login:** Separate authentication flow through the Login Server.
- **`RequestedConnectionContext`:** Connection requesting login.
- **`ConnectionContext`:** Officially logged-in connection.
